# 训练室

给养成党用的《明日方舟》小工具，帮你盘盘仓库，看看还能练谁。

仓库攒了不少材料，想给喜欢的干员补个专三、拉到精二，或者把模组再升一级。训练室会读取森空岛的仓库和干员养成状态，连加工站能合成的材料一起算，列出你现在够材料完成的培养项目。

**[下载最新测试版](https://github.com/WangXiangpu0916/Arknights-Training-Room/releases)** · [看看最近更新了什么](release-notes.md)

适用于 Windows 10/11，当前支持国服简中数据。用森空岛 App 扫码连接，规划在本地计算。

> [!NOTE]
> 项目目前处于测试阶段，所有已发布版本均为测试版，可能存在缺陷或不兼容变更。

## 给下一位毕业干员做点准备

### 专精、精英化、模组，都能查

- 专精规划会根据每个技能的当前等级，找出还能往上练的技能，优先展示专二到专三。想连着练，就打开连续专精模式，查看能跨两级及以上的路线；正在训练室里专精的技能，也能接着看训练完成后的材料是否够用。
- 精英化规划会把升级经验、升级和晋升的龙门币、材料一起算进去，支持从未精英化一路规划到精二。
- 模组规划按每个模组分别计算，支持解锁和升到三级，也会检查干员的精英阶段、等级与材料门槛。同一位干员有多个模组，可以逐个看。

三类规划都能搜索和筛选，支持拼音首字母查找。点开某个项目，可以查看总需求、各阶段用量和合成配方。

### 加工站能做的，也算进来

材料还没合成，不代表练不了。训练室会沿配方往下找原料，计算仓库里现有材料能合成多少；几条配方用到同一种原料时，也会扣掉已经用过的那一份。仓库页还能查看材料用途、描述和可合成数量。

计算只用仓库的本地副本，不会消耗或改动游戏内库存。列表里的每个项目都从同一份库存单独计算，连续路线则会逐阶段扣除材料；多个项目同时显示可行，不代表材料够把它们一起做完。

### 活动无限池，也能提前盘一盘

打算趁活动多囤某种材料？在仓库页把它设为“无限供应”，再到规划页开启“使用无限池材料”，就能看看这种材料不再卡进度时，还能多练谁。专精页也可以单独把技巧概要视为无限。

这个开关只影响模拟，仓库里实际有多少，仍然显示多少。

### 看着养成进度一点点涨

统计页可以查看干员持有、精英化、专精三级技能、模组解锁和三级模组的进度，并按星级查看明细。想看整个图鉴的完成度，或只盘自己已有的干员，都可以切换。

干员页把精英阶段、等级、技能等级、专精和模组状态放在一起。点开技能图标还能查看各等级效果和升级材料，翻档案时顺手就能查。

## 开始用

1. 到 [GitHub Releases](https://github.com/WangXiangpu0916/Arknights-Training-Room/releases) 下载安装包或 Portable 单文件版，安装或直接运行。
2. 首次启动，点击“使用森空岛 App 扫码连接”。
3. 在手机上的森空岛 App 确认登录，再选择绑定的《明日方舟》角色。
4. 等待同步完成，就可以翻翻专精、精英化和模组规划，看看这次想练谁。

账号数据可以手动刷新，也可以在设置里开启“启动时自动刷新”。再次打开时，首页会先显示仍然适用的上次规划，后台加载完成后更新，并保留筛选、焦点和滚动位置；首次使用或缓存不匹配时会重新加载。是否联网同步账号，仍由“启动时自动刷新”决定。

界面有黑色、浅色和跟随系统三种主题。游戏资源会在启动时及每小时自动检查，也可以在设置页手动更新；新干员、技能、模组、材料和图片随资源包一起更新，无需每次都重装应用。下载时可以继续使用，更新失败会保留已有资源。

## 使用时留意这几件事

- 模组首次开启前，还需要在游戏内确认模组任务和信赖条件，森空岛当前接口没有提供这两项数据。
- 森空岛暂未稳定提供干员本级已积累的经验，缺失时按本级 0 经验计算；如果接口返回了该字段，会扣除这部分已有经验。
- 森空岛接口变化或同步失败时，应用会提示错误并保留旧缓存。规划对应的是上次成功同步的状态，培养后记得刷新。
- 当前构建没有商业 Authenticode 签名，首次运行可能遇到 Windows SmartScreen 的“未知发布者”提示，可先核对发布产物附带的校验和。

## 数据与开发说明

<details>
<summary>账号数据存在哪里，怎么清理？</summary>

数据默认保存在 `%APPDATA%/arknights-training-room`：

- `credentials.bin`：与原版兼容的 AES-256-GCM 密文，密钥由 Windows DPAPI 保护；继续读取原 `Local State`，无需重新登录
- `account-cache.json`：最近一次成功的账号快照，不含登录凭据
- `settings.json`：无限材料、主题、选中 UID 和自动刷新开关
- `game-data/`：最近一次成功的完整游戏资源快照（数据、metadata、图片与 manifest）
- `game-data.backup/`：上一份可用快照；未提交事务在启动时自动恢复
- `app.log` / `app.log.1`：轮转日志，最大约 1 MB，敏感长字符串会被替换为 `[REDACTED]`
- `webview2/`：浏览器缓存及上次界面状态；清理账号缓存后不再显示旧账号的界面状态

设置页的“清理账号缓存”保留登录凭据；“退出 / 删除认证”只删除加密凭据。规划使用账号快照的副本，不会修改真实仓库缓存。

</details>

<details>
<summary>规划怎么算，资源怎么更新？</summary>

每次可行性判断都复制真实仓库。加工按整数批次递归扣除输入，只计入确定产物，忽略随机副产物；支持多层配方、共享原料和多产物。遇到未知材料、缺失配方、无效产量或循环依赖时，会判为不可行。

单阶段专精按 `M2→M3 > M1→M2 > M0→M1` 排序，每个候选独立计算。连续专精只展示跨度至少两级的路线；连续模式把上一阶段的剩余库存交给下一阶段。所有规划在本地按配方计算，运行时不使用 LLM、Agent、AI API 或 AI Token。

无限材料用集合状态表示，不用大数字代替。某种产物只有在自身被设为无限，或配方的每种输入都能由无限材料合成时，才会被视为无限；计算结果会保留对无限材料的依赖信息。

游戏资源与应用版本独立，完整资源包包含数据、metadata 和图片，更新时检查兼容性并支持失败回滚。资源 schema 不兼容时，会提示升级应用并保留旧资源。[资源架构与发布流程](docs/RESOURCE_UPDATES.md)

森空岛使用非公开接口，没有公开 SLA、固定 Token 生命周期或频率额度。账号只在手动刷新或启用启动刷新时联网同步，并按返回错误码刷新签名 Token 或凭据。

GitHub 仓库为私有时，未认证的更新器无法读取 Releases，应用会提示错误并写入脱敏日志。应用内自动更新需要公开的发布仓库或更新源，不能把私人访问令牌写进客户端。

</details>

<details>
<summary>从源码运行与构建</summary>

要求：Windows 10/11、Node.js 22+、Rust MSVC stable、Visual Studio C++ Build Tools / Windows SDK。运行时使用系统 Microsoft Edge WebView2；安装器在缺少时下载引导程序。最终用户不需要 Node.js 或 Rust。

```powershell
npm ci
npm test
npm run dist
```

构建产物位于 `release/`：NSIS 安装包、Portable `.exe`、更新元数据和校验和。`npm run build` 与 `npm run dist` 都会覆盖唯一的 `release/win-unpacked`，不会自动更改版本号。直接运行其中的 `训练室.exe` 可检查本地最新构建。

开发启动：

```powershell
npm install
npm start
```

### 测试

```powershell
npm test
```

测试覆盖精英化与模组连续路线、经验/龙门币累计、共享库存递归合成、多产物整数批次、循环配方、认证续期、旧数据、资源回滚、发布流程及静态 UI 契约，另有 31 组迁移前完整结果哈希对照。

`npm run qa:desktop` 检查窗口、输入、筛选、排序、详情和截图；`npm run qa:resource` 检查真实 HTTP 下载、失败保留、图片切换和重启恢复；`npm run qa:packaged` 使用显式启用测试端口的优化构建检查打包资源，然后恢复正式构建并同步本地应用。生产构建禁止测试端口和测试路径覆盖。架构、测量方法与验收限制见 [迁移报告](docs/ELECTRON_TAURI_MIGRATION.md)。

`npm run benchmark:performance` 测量八组原生核心计算；`npm run benchmark:desktop` 构建优化 QA 版本，测量三次完整窗口流程，再恢复正式构建并同步。桌面测量默认复制本地账号快照并匿名化，不复制凭据；可用 `ATR_PERF_PROFILE` 指定测试数据目录。结果保存在 `output/performance/`。

真实账号的完整扫码和在线同步需要账号持有人操作，未登录时无法完成该账号的端到端验证。数据契约基于 2026-08 仍维护的实现；接口变化时会显示错误并保留旧缓存。

</details>
